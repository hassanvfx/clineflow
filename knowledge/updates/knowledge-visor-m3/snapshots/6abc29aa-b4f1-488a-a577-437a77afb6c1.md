# Goal

Replace the first brochure shell with a compact, product-quality read-only
knowledge explorer that makes the frozen Ad Crush record useful on first read.

# Task Contract

- Intended outcome: Compress the masthead and chapter framing, expose useful
  record summaries immediately, reduce empty-state weight, and render Activity
  as a readable event list that opens complete detail only on demand.
- Observable success criteria: The canonical fixture shows a one-screen project
  header and useful content; each Activity event has a compact date, title,
  source and preview without raw tenant IDs or stretched columns; no-data states
  are subordinate; keyboard and modal reading remain available.
- Constraints and non-goals: Preserve source fidelity, offline/static operation,
  four-tab order, the one read-only reader, and no new dependency. Do not invent
  Sparks or turn journal summaries into unsupported causal claims.
- Open questions and assumptions: A source-grounded candidate queue may be shown
  for absent Sparks, but only as source coverage—not as a published learning.

# Execution Boundaries

- Authorized scope and exclusions: Dashboard presentation model, browser shell,
  styles, fixture presentation data, tests, manifests and this journal. Exclude
  canonical Ad Crush source, live connections, external packages and publication.
- Affected interfaces, owners, and relevant side effects: Presentation HTML and
  source reader behavior change; facts and observation validation stay stable.
- Escalate before changing source contracts, installing visual libraries, adding
  background services, or publishing the frozen sample.
- The current agent owns implementation and final integration checks.

# Work Log

## 2026-09-11 23:48 UTC - Visual review failure accepted

User review of the canonical Ad Crush sample found two concrete failures: a
full-screen empty Sparks state dominated its chapter, and the Activity grid
allocated most of the viewport to empty columns while exposing an unhelpful raw
tenant identifier. The screenshots are the design-review evidence for this M3
slice. The old presentation is not considered acceptable evidence of M2 visual
quality.

## 2026-09-12 00:03 UTC - Compact reader implemented

Rebuilt the report shell around a short project header, useful first-screen
context, ledger and journal entry points, and on-demand record search. The empty
Sparks state is now a compact review status plus clearly labelled source coverage;
it does not pretend that journal sources are published lessons. Activity is now
grouped by day, shows four concise records before a disclosure control, and opens
the full normalized event only in the reader. Raw tenant identifiers were removed
from the primary feed and retained only in complete record detail.

The journal reader now extracts Goal, Task Contract, Decisions, Verification
Results, and Open Issues before offering the normalized source. This preserves
the source while making the first reading layer useful.

## 2026-09-12 00:13 UTC - Rich source formatting repaired

The first structured-reader pass still compacted each journal section into plain
text, which erased the journal's lists, emphasis, inline code, links, and nested
headings. The reader now uses the existing sanitized CommonMark rendering for
each extracted section. It retains the compact section framing, displays rich
document structure in the reader, and keeps the exact normalized source behind
its existing disclosure. The test fixture now includes a small CommonMark-shaped
renderer so the formatting contract is exercised without a network dependency.

## 2026-09-12 00:30 UTC - Ledger reader repaired

Visual review found that the generic structured-data reader was rendering a
ledger's storage index (`records`) as duplicate UUID bullets. Ledger documents
now receive their own reader model: a compact version/update facts strip and a
catalogue of named records. The first six records are visible, remaining records
are explicitly disclosed, and opening one replaces the same reader surface with
its status and full statement. UUIDs and source fragments remain behind explicit
inspection controls and never appear in the primary ledger view.

# Decisions

- Progressive disclosure means summary first, then an explicit reader—not merely
  putting raw records in large boxes. Raw identifiers stay available in the reader
  only. Empty states communicate availability in a compact secondary panel.
