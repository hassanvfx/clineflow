# Goal

Make ClineFlow's preferred planning format adaptive, evidence-first, and
available to fresh and updated installations.

# Task Contract

- Intended outcome: distribute a managed planning guide, decision-gate rules,
  and an Engineering Journal template that distinguishes pending decisions from
  open issues.
- Observable success criteria: fresh installation and historical-update tests
  receive the guide and template; release certification passes.
- Constraints and non-goals: preserve user-authored project knowledge and
  documentation; do not create a separate workflow or alter migration state.
- Open questions and assumptions: the existing manifest-managed update path can
  refresh the new managed guide without a migration-schema change.

# Execution Boundaries

- Authorized scope and exclusions: ClineFlow template rules, procedures,
  managed runtime documentation, journal template, release manifest, version,
  and lifecycle tests only.
- Affected interfaces, owners, and relevant side effects: all supported agent
  instruction blocks and the new-journal format; existing project journals stay
  unchanged.
- Escalate before changing requirements, external behavior, authority, ownership, dependencies, or acceptance criteria: no additional escalation expected.
- Delegation integrator and remaining integration checks, when applicable: one
  cohesive handoff; the current agent owns release certification.

# Handoff Topology

- Selection: single handoff, because the guide, rules, template, and release
  payload form one managed planning contract.
- Parent integrator and final end-to-end acceptance, when applicable: current
  agent verifies release validation, fresh install, and update migration.
- Milestones: one managed-template handoff; inputs are the approved reference
  plan and existing ClineFlow contract, outputs are the new guide and updated
  instructions, proof is lifecycle certification, and rollback is the standard
  manifest-backed updater transaction.

# Existing Approaches

- Relevant project patterns or established approaches considered: existing
  handoff topology rules, managed `.clineflow` procedures, and the task journal
  template.
- Why the selected approach fits, or why a novel approach is necessary: a
  managed guide keeps detailed preferred format out of concise agent rules while
  preserving a discoverable, updateable contract.

# Planned Proof

- Deterministic checks to run and the rules they enforce: release validation;
  installation, migration, and release-contract tests assert distribution.
- Integration checks to run: full `./tests/certify-release.sh`.
- Remaining judgment or coverage limits: tests prove availability and contract
  markers, while the guide's practical quality is reviewed against the supplied
  reference plan.

# Decisions

- Use a managed `.clineflow/PLANNING.md` guide, rather than a personal skill or
  a second journal type, so fresh and updated installations share one contract.
- Make the Engineering Journal canonical; create `docs/plans/` only for
  long-lived, externally shareable, or unusually large plans.
- Stop affected handoffs at material decision gates while independent authorized
  work can continue.
