# Goal

Define and enforce the report-owned observations/Sparks contract so an agent can
propose reusable project learning without allowing unsupported claims into the
brochure.

# Task Contract

- Intended outcome: Add optional source-bound Sparks, explicit evidence states,
  cited source locators, and a bounded no-Spark fallback to the observation model.
- Observable success criteria: Valid candidates pass structural checks; unknown
  citations, empty origins, duplicate IDs, unsupported states, and contested claims
  without challenging evidence fail with actionable errors.
- Constraints and non-goals: No canonical schema change, LLM invocation, source
  mutation, causal inference, confidence score, public publication, or requirement
  that every journal produce a Spark. Existing observations remain compatible.
- Open questions and assumptions: Exact semantic relevance still requires human
  review; deterministic validation proves shape, identity, and locator resolution.

# Execution Boundaries

- Authorized scope: Dashboard observe/validate/presentation code, viewer Spark
  fallback, tests, manifests and this journal. Exclude canonical sources/sibling.
- Affected interfaces: observations/presentation JSON gain additive `sparks` and
  harness metadata; old candidates without sparks remain accepted.
- Escalate before a provider, dependency, canonical relation, or write-back path.
  Current agent is integrator; no delegation.

# Handoff Topology

- Selection: single handoff. The validator, fallback presentation, and tests form
  one independently verifiable contract consumed by the brochure shell.
- Entry: M0 report facts. Output: `sparks` schema, validation diagnostics, and
  honest empty state. Proof: positive and adversarial fixture cases plus dashboard
  boundary suite. Rollback: omit Spark candidates while preserving facts and prior
  observation rendering if compatibility fails.

# Existing Approaches

- Extend the existing facts → observations → presentation stages and source-ID
  validation. Keep exact source locators in candidate records rather than inventing
  a graph database or treating ledger synchronization as causal evidence.

# Planned Proof

# Decisions

- Allowed evidence states are emerging, supported, contested, and superseded.
- Every Spark requires at least one origin; contested Sparks require challenging
  evidence. Unknown source IDs and blank locators are rejected.
- Empty Sparks are valid and informative; no minimum learning count is imposed.
- Structural acceptance is not semantic truth. Agent-produced candidates remain
  interpretations until a human reviews cited passages and limitations.
