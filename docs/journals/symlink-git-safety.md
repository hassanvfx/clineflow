# Symlink Git Safety - Implementation Journal

## Overview
Fix critical issue where symlinks generated by setup-refs.sh could be committed to git, causing conflicts between developers with different local paths.

## Problem Statement
- `setup-refs.sh` creates symlinks in `clineflow/` directory pointing to local repositories
- These symlinks contain absolute paths specific to each developer's machine
- If committed, they break for other developers and cause merge conflicts
- Simply adding to `.gitignore` makes symlinks invisible in VSCode, defeating their purpose

## Solution Approach
Use `.git/info/exclude` instead of `.gitignore`:
- Acts like `.gitignore` but is local-only (never committed)
- Keeps symlinks visible in VSCode
- Automatically excludes them from git operations
- Each developer maintains their own exclude rules
